# Diagnóstico do ecossistema

para saber em que estado o MeasureSoftGram chegou a este semestre antes de
decidir o que construir.

Foram analisados **sete repositórios** - Action, CLI, Core, Docs, Front, Parser e
Service - avaliando arquitetura, integridade do modelo de qualidade, segurança,
cobertura de testes e integração contínua.

## Panorama do ecossistema

O MeasureSoftGram não é um programa único: é um ecossistema de módulos
independentes em repositórios separados. Hoje ele existe em **duas versões
paralelas que não coincidem**.

A análise cobriu os sete repositórios **centrais** da organização, sem prefixo de
semestre. Já a documentação oficial, escrita em julho de 2026, lista **nove
repositórios ativos** com prefixo `2026.1-`, incluindo dois módulos que não
existem no conjunto central: **AI** (servidor MCP) e **Plugin** (extensão VS Code).

:::warning[Achado estrutural]
A documentação descreve um ecossistema de nove módulos hospedado nos
repositórios de semestre, enquanto o trabalho de consolidação de 2026.1 migra
para repositórios centrais. **Os dois modelos coexistem sem que nenhum seja a
fonte da verdade.**
:::

| Módulo | Responsabilidade | Stack | Presente |
| --- | --- | --- | --- |
| Core | Núcleo de cálculo do modelo de qualidade | Python | Sim |
| Parser | Normaliza dados de entrada para o Core | Python | Sim |
| Service | Backend REST, orquestra cálculo e persiste | Django | Sim |
| Front | Interface web e dashboards | Next.js | Sim |
| CLI | Ferramenta de linha de comando | Python | Sim |
| Action | Integração com pipelines de CI | TypeScript | Sim |
| AI | Servidor MCP para assistentes de IA | Python | **Ausente** |
| Plugin | Extensão para editor VS Code | TypeScript | **Ausente** |

### Perda de histórico nos merges

Os commits "Sincronização de repositório - 2026.1" são *squashes* de grande
porte: um único commit traz 2.065 linhas alteradas em 45 arquivos no CLI. Todo o
trabalho de um semestre - autoria individual, motivação de cada mudança,
possibilidade de bissecção - colapsa em um commit só.

## Integridade do modelo de qualidade

Este é o achado mais grave. **O motor de cálculo publicado não corresponde ao
código versionado**, e os dois modos de uso produzem notas diferentes para o
mesmo software.

O repositório Core declara a versão **1.5.3**. No PyPI existe **msgram-core
1.5.4**, publicado a partir de código que não está no repositório. A comparação
dos dois pacotes revela correções semânticas reais:

```python
# aggregated_normalized_measures.py - medida ci_feedback_time
-    gain_interpretation=1,
+    gain_interpretation=-1,      # sentido da metrica invertido
-    max_threshold: float = 0.33,
+    max_threshold: float = 0.66,  # limiar dobrado
+    if int(total_builds) == 0:
+        return NO_BUILDS_NEUTRAL_SCORE

# util/run_time_data_operations.py - bug de matriz não-quadrada
-    return abs(sum / (size * size))
+    return abs(sum / (size_1 * size_2))
```

:::danger[Consequência]
A nota de qualidade calculada hoje **não é reproduzível** a partir do código
versionado. O modelo de qualidade, que é o produto do projeto, deixou de ser
auditável.
:::

### Três versões do Core em circulação

| Onde | Versão | Papel |
| --- | --- | --- |
| Service (produção) | 1.4.9 | Fluxo hospedado: dashboards e histórico |
| CLI (instalação limpa) | 1.5.4 | Fluxo offline: cálculo local via terminal |
| Repositório Core | 1.5.3 | A suposta fonte da verdade |

A documentação afirma que os dois modos "compartilham o mesmo motor de cálculo".
Na prática, o Service está duas versões atrás do CLI, e **nenhum dos dois roda o
código versionado**.

## Segurança

Cinco achados no Service, um deles com exposição direta de dados pessoais em
endpoint público.

| Achado | Gravidade |
| --- | --- |
| `GET /users/` expõe e-mail de todos os usuários sem autenticação | Crítico |
| Django 4.0.6 - sem suporte desde abril de 2023 | Crítico |
| Token OAuth do GitHub armazenado em texto plano | Atenção |
| Produção sem TLS, com endurecimento desativado por padrão | Atenção |
| CORS e CSRF apontando para infraestrutura desativada | Atenção |

O caso mais serio: o Django REST Framework não define
`DEFAULT_PERMISSION_CLASSES`, e o padrão nesse caso é `AllowAny`. Todo viewset
sem permissão explicita fica aberto - incluindo a listagem completa de usuários
com seus e-mails.

## Integração e entrega continuas

A infraestrutura opera em duas velocidades muito distintas.

**Service - o padrão de referência.** A modernização de 2026.1 e trabalho de
qualidade profissional: dependências com `uv` e lockfile, actions fixadas por
SHA, Postgres 18 nos testes, Docker multi-estágio, deploy resiliente,
*healthcheck*, proxy reverso nginx e quatro dashboards Grafana provisionados.

**Os demais - parados em 2024.** Actions descontinuadas (`checkout@v3`,
`setup-node@v3`, `setup-python@v4`), action do SonarCloud arquivada e fixada em
`@master`, e chaves do Sonar divergindo em três padrões diferentes.

:::warning[Nenhum portão de qualidade e bloqueante]
Os quatro arquivos `codecov.yml` marcam `informational: true`, e o `.coveragerc`
do Service não define `fail_under`. Na prática, **a cobertura de testes nunca
reprova um pull request** - num projeto cuja finalidade é justamente medir
qualidade de software.
:::

## Divida técnica acumulada

**Front - a maior superfície, a mais desatualizada.** São 18.936 linhas de
TypeScript sobre uma base cujas dependências pararam em 2022: Next.js 12.2.2
(fora de suporte), `axios@0.27.2` e Node 18 no CI, também em fim de vida.

:::warning[Divergência não explicada]
O deploy do Service roteia um conteiner `front:3000` e registra que "o Front tem
o seu próprio deploy". Existe, portanto, **um frontend em produção que não
corresponde a este código**.
:::

**Action - parada há dois anos.** O manifesto declara `using: 'node16'`, runtime
já removido pelo GitHub, e o diretório `dist/` versionado foi gerado pela última
vez em setembro de 2024.

Em contrapartida, os marcadores de divida no código são poucos: apenas **14
ocorrências** de `TODO`, `FIXME` ou `HACK` em cerca de 32 mil linhas de Python.

Vale registrar o que está sólido, porque não é pouco.

| Ponto | Detalhe |

| **O núcleo matemático está bem testado** | O Core alcança 92% de cobertura, com suíte que passa integralmente. O coração do modelo de qualidade - a parte mais difícil de reescrever - é a mais bem cuidada. |
| **A modernização do Service e profissional** | Settings divididos com docstrings que explicam cada decisão, actions fixadas por SHA, Grafana provisionado. E o padrão a replicar. |

| **Disciplina de estilo mantida** | Zero ocorrências de flake8 em 100% do código Python. |

## Plano de ação priorizado

### Bloqueante - correção imediata (dias)

1. **Corrigir a fixture do Parser.** Duas *strings*; o branch `develop` está vermelho.
2. **Fechar o endpoint `GET /users/`.** Adicionar `DEFAULT_PERMISSION_CLASSES`.
3. **Estabilizar a dependência do CLI.** Decisão de produto, não de infraestrutura.

### Crítico - integridade e segurança (semanas)

4. **Recuperar o código do msgram-core 1.5.4** e versiona-lo no Core.
5. **Alinhar a versão do Core** nos três consumidores.
6. **Atualizar o Django** para 4.2 LTS e cifrar o `github_access_token`.
7. **Habilitar TLS na borda** e ativar as flags de `production.py`.

### Estrutural - governanca do ecossistema (semestre)

8. **Decidir entre repositórios centrais ou de semestre.**
9. **Replicar o padrão de CI do Service** nos outros seis repositórios.
10. **Tornar bloqueante ao menos o portão de `patch`** do Codecov.
11. **Atualizar ou aposentar Front e Action explicitamente.**

## Método e limitações

O diagnóstico distingue o que foi **verificado por execução** do que resulta de
leitura de código e configuração.

| Verificado por execução | Não verificado |
| --- | --- |
| Suites de teste de Core, Parser e CLI | Suíte do Service - exige Postgres |
| flake8 nos quatro repositórios Python | Suites de Front e Action |
| Comparação dos pacotes 1.5.3 e 1.5.4 do PyPI | Estado real da CI no GitHub |
| Histórico Git completo dos sete repositórios | Repositórios AI e Plugin - ausentes |
| Rotas e permissões do Service por inspeção | Ambiente de produção em execução |
