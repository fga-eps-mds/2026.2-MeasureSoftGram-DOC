# Templates e fluxos

Ponto único para encontrar os templates e os fluxos da equipe. Os templates do
GitHub aparecem sozinhos ao criar uma issue ou um PR no repositório
[2026.2-MeasureSoftGram-DOC](https://github.com/fga-eps-mds/2026.2-MeasureSoftGram-DOC/issues/new/choose).
Os da documentação ficam em `docs/_modelos/`.

## Fluxos

| Fluxo | O que define |
| --- | --- |
| [Fluxo de trabalho](/docs/processo/fluxo-de-trabalho) | Branch → `develop` do fork → `develop` central → `main`, nomes de branch, Conventional Commits, PR, revisão e CI |
| [História de usuário](/docs/processo/historia-de-usuario#ciclo-de-vida-da-us) | Ciclo da US do rascunho à validação do PO, com critérios INVEST, DoR e DoD |
| [Gestão do backlog](/docs/planejamento/backlog) | Taxonomia (épico, US, task, bug), regra de validação com o PO, DoR e DoD por tipo |
| [Guia de documentação](/docs/equipe/guia-documentacao) | Padrão de página, onde registrar cada coisa e checklist de revisão |

## Issues (GitHub e Zenhub)

| Template | Título | Use para |
| --- | --- | --- |
| [Épico](https://github.com/fga-eps-mds/2026.2-MeasureSoftGram-DOC/blob/main/.github/ISSUE_TEMPLATE/epico.md) | `[MSGXX] Nome` | Entrega macro de valor ou de correção |
| [História de usuário](https://github.com/fga-eps-mds/2026.2-MeasureSoftGram-DOC/blob/main/.github/ISSUE_TEMPLATE/historia-de-usuario.md) | `[USXX.YY] Nome` | Funcionalidade percebida pela persona ([guia](/docs/processo/historia-de-usuario)) |
| [Task técnica](https://github.com/fga-eps-mds/2026.2-MeasureSoftGram-DOC/blob/main/.github/ISSUE_TEMPLATE/tarefa.md) | `[TASKXX.YY] Nome` | Infra, CI, refatoração, sustentação |
| [Defeito](https://github.com/fga-eps-mds/2026.2-MeasureSoftGram-DOC/blob/main/.github/ISSUE_TEMPLATE/defeito.md) | `[BUGXX.YY] Nome` | Falha em comportamento já existente |

`XX` é o número do épico pai; use `00` para itens transversais.

## Pull request

O [template de PR](https://github.com/fga-eps-mds/2026.2-MeasureSoftGram-DOC/blob/main/.github/pull_request_template.md)
pede a issue, a etapa do fluxo, o que muda e por quê, como testar, evidências,
o impacto na qualidade e dois checklists (autor e revisor). Os critérios de um
bom PR estão no [Fluxo de trabalho](/docs/processo/fluxo-de-trabalho#4-pull-request).

:::caution[Repositórios do produto]
Os repositórios `2026.2-*` (Core, Parser, Service, Front, CLI) ainda usam
templates antigos de 2026.1, e AI, Action e Plugin não têm templates. Copiar a
pasta `.github/ISSUE_TEMPLATE/` e o `pull_request_template.md` deste repositório
para eles (task de saneamento, épico MSG03).
:::
