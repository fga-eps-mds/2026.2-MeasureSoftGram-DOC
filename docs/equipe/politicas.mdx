# Políticas de trabalho

## Branches, commits e pull requests

O padrão de branches (`feat/`, `fix/`, `task/`, `docs/`), commits (Conventional
Commits) e o caminho branch → `develop` do fork → `develop` central → `main`
estão no [Fluxo de trabalho](/docs/processo/fluxo-de-trabalho).

## Política de code review

- Todo Pull Request precisa de aprovação de ao menos um outro integrante.
- O PR segue o [template](/docs/processo#pull-request): o que muda e
  por quê, como testar, evidências e impacto na qualidade.
- O autor não faz merge do próprio PR sem aprovação.
- A CI precisa estar verde antes da revisão e do merge.
- Primeira revisão em até 2 dias úteis; PR parado vira bloqueio na daily.
- A revisão é humana: não pode ser feita por IA.

## Código de conduta

A equipe segue o código de conduta da organização fga-eps-mds. Comportamentos
que violem o código devem ser comunicados aos monitores da disciplina.
